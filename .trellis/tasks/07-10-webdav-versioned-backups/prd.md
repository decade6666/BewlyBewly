# 更新 WebDAV 版本化备份同步

## Goal

将 WebDAV 同步从单个固定文件升级为目录中的版本化备份，让用户能够恢复最近 20 次中的任意一次同步结果，同时避免覆盖已有备份。

## Background

- 当前默认路径是固定文件 `/bewly/settings.json`，上传和下载分别对完整路径执行单次 `PUT` 与 `GET`，目录逻辑只负责创建该文件的父目录（`src/logic/webdavSettings.ts:3`、`src/logic/storage.ts:237-243`、`src/logic/webdav.ts:79-191`）。
- 所有 WebDAV 网络请求通过扩展后台执行，以绕开内容脚本的跨域限制；现有消息合同只有测试、上传和下载（`src/logic/webdav.ts:17-65`、`src/background/messageListeners/webdav.ts:13-47`）。
- 远端内容使用版本 1 信封，包含毫秒时间戳、设置和屏蔽词；恢复时保留本机 WebDAV 连接配置（`src/logic/settingsSync.ts:7-16`、`src/logic/settingsSync.ts:87-159`）。
- 当前对话框只有覆盖本地数据的内联确认，没有远端文件列表或版本选择（`src/contentScripts/views/WebdavSettingsDialog.vue:302-338`、`src/contentScripts/views/WebdavSettingsDialog.vue:486-523`）。
- 当前没有把旧单文件路径迁移为目录路径的逻辑，也没有目录列举、备份轮转或选定版本恢复测试（`src/logic/settingsMigration.ts:1-45`、`src/tests/webdavSettings.spec.ts`、`src/tests/settingsSync.spec.ts`、`src/tests/linuxDoMigration.spec.ts:1325-1521`）。

## Requirements

### R1 — Directory path and legacy compatibility

- WebDAV 同步路径按文件夹处理，默认值为 `/bewly/`。
- 升级时将现有单文件路径转换为对应父目录，并在本地保留识别原远端单文件所需的信息；旧默认 `/bewly/settings.json` 和自定义旧文件路径都必须兼容。
- 原远端单文件作为“旧版备份”出现在恢复列表中，计入最近 20 份，并在成为最早版本时按相同规则淘汰。
- 若旧版文件暂时无法读取或不是有效版本 1 信封，健康的新版本列表仍可使用；该旧文件不参与排序或删除，并显示兼容警告。上传结果按清理部分成功处理，后续上传再次尝试识别，避免因一个损坏旧文件阻断全部恢复或被误删。
- 用户主动改用其他目录后，不得继续把旧目录中的单文件混入新目录的列表或轮转。

### R2 — Immutable version creation

- 每次上传创建新备份文件，不覆盖任何已有版本。
- 文件名包含可排序的 UTC 日期时间标记，精确到毫秒；选择列表将其转换为当前设备的本地日期时间。
- 同一毫秒发生命名碰撞时追加稳定序号并使用禁止覆盖的条件写入，直至创建唯一文件或明确失败。

### R3 — Retention and upload outcome

- 受管理备份集合最多保留最近 20 份，集合包括新版命名文件和仍存在的已知旧版单文件，但不包括目录中的其他文件。
- 采用“先上传、后清理”：新文件成功创建后，按时间从最早开始逐个删除所有超额版本，直到只剩最近 20 份。
- 新文件上传失败时不得删除任何已有备份。
- 清理失败不回滚新备份，按“部分成功”处理：更新最后同步时间，明确提示上传成功但清理失败，并在下次成功上传后重新收敛全部超额版本。

### R4 — Version selection and restore

- 点击下载后先读取远端备份列表，在现有 WebDAV 对话框内按时间从新到旧显示可选版本，并默认选中最新版本。
- 列表为每个版本显示本地日期和时间，并明确标记旧版备份。
- 同一选择区域持续显示“将覆盖本地设置和屏蔽词”的警告；改变选择不触发恢复，用户点击一次“恢复所选备份”后才下载并应用该版本。
- 无可用备份、目录读取失败、所选备份消失、下载失败或内容无效时，不改变本地设置和屏蔽词，并显示明确状态。

### R5 — Existing compatibility boundaries

- 保持手动同步模式、单操作锁、连接测试、后台传输、任意 WebDAV 端点权限和现有鉴权方式。
- 保持版本 1 远端信封及其设置/屏蔽词内容，不引入远端数据格式迁移。
- 恢复任意版本时继续保留本机 WebDAV 配置（包括旧版文件定位）；该定位不得进入远端信封，并以所选信封的时间戳更新最后同步时间。
- 所有完全失败、部分成功和完全成功结果必须可区分；不得把清理失败显示为完全成功。

## Acceptance Criteria

- [ ] **R1:** 新配置和空路径使用 `/bewly/`；路径在上传、列举和下载中始终按目录处理。
- [ ] **R1:** 旧默认及自定义单文件路径升级为对应父目录，且原远端文件仍可在新版列表中按时间恢复。
- [ ] **R1/R3:** 旧版文件计入 20 份并可在成为最早版本时删除；目录中的其他文件永远不进入计数且不会被删除。
- [ ] **R1/R3:** 无法读取或校验的旧版文件不会阻断健康版本的列举/恢复，也不会在时间未知时被删除；界面显示兼容或清理警告，后续上传会重试识别。
- [ ] **R1:** 用户保存不同目录后，旧版文件定位信息被清除，不会跨目录参与恢复或清理。
- [ ] **R2:** 连续上传两次会生成两个含可解析 UTC 毫秒时间标记的不同文件，已有文件内容不变。
- [ ] **R2:** 模拟同毫秒碰撞时会创建带序号的唯一文件；若服务器无法保证禁止覆盖，则明确失败而不执行无条件覆盖。
- [ ] **R3:** 远端已有 20 份受管理备份时，新上传先创建第 21 份，再删除最早版本，最终保留最新 20 份。
- [ ] **R3:** 上传失败时原有备份不变；清理部分失败时新备份可恢复、最后同步时间更新、界面显示警告，下一次上传会重试清理全部超额版本。
- [ ] **R4:** 下载流程先列举版本，按本地日期时间从新到旧显示并默认选中最新版本；旧文件有明确标记。
- [ ] **R4:** 仅改变选择不会发起下载；确认后恢复的内容严格来自所选版本，而不是固定文件或默认最新版本。
- [ ] **R4:** 空目录、列举错误、选择后文件被删除、下载错误、JSON 解析错误和不支持的信封版本都不会改变本地数据，并显示相应反馈。
- [ ] **R5:** 连接测试、后台消息边界、手动操作锁、版本 1 信封和对话框键盘/焦点行为继续通过现有及新增验证；旧版文件定位不上传且在恢复后保留。

## Out of Scope

- 自动同步、后台定时同步或跨设备冲突合并。
- 改变 WebDAV Basic Auth、任意端点权限或请求取消策略。
- 改变版本 1 信封、同步数据范围或服务器账户/配额管理。
- 新增第三方运行时依赖、扩展权限、构建脚本或发布流程。
